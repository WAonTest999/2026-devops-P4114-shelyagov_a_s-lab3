# REST API

Базовый путь `/api`. Тело запросов — JSON, заголовок `Content-Type: application/json`. Ошибки: `{"error":"Описание"}`. Все изменяющие запросы браузера проходят проверку Origin; произвольный CORS не включён. Клиент и API доступны с одного домена через Nginx.

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `GET /health` | Любой | Liveness |
| `GET /ready` | Любой | Проверка подключения к БД |
| `POST /register` | Любой | `{"login":"alice","password":"password123"}` |
| `POST /login` | Любой | Те же поля; возвращает пользователя и cookie `session` |
| `POST /logout` | Любой | Удаляет серверную сессию и cookie |
| `GET /me` | Пользователь | `id`, `login`, `admin` |
| `GET /events` | Любой | Список концертов по дате |
| `POST /events` | Администратор | Создать концерт |
| `PUT /events/{id}` | Администратор | Изменить название и дату, передать исходный размер зала |
| `DELETE /events/{id}` | Администратор | Удалить концерт вместе с бронями |
| `GET /events/{id}/bookings` | Любой | Занятые места: `id`, `seat`, `mine`; чужие `id` скрыты (0) |
| `POST /events/{id}/bookings` | Пользователь | `{"seats":[1,2,11]}`; атомарная бронь |
| `DELETE /bookings/{id}` | Владелец | Отмена своего места |

Пример концерта:

```json
{"title":"Отчётный концерт","starts_at":"2027-05-20T15:00:00Z","rows":10,"cols":10}
```

Время передаётся в RFC3339, сохраняется как `TIMESTAMPTZ`. Интерфейс показывает местное время браузера. Места нумеруются с 1: `seat = (ряд - 1) * cols + место`. На одного пользователя нет общего лимита, но один запрос может содержать от 1 до 10 различных мест. До подтверждения временное удержание мест не создаётся. Если другое окно заняло место первым, сервер вернёт 409, а клиент обновит схему. Для прошедших концертов создание брони закрыто.

Сессии живут 24 часа и доступны всем репликам сервера через общую БД. Cookie имеет `HttpOnly`, `SameSite=Strict`; в облачном варианте включён `Secure`. `DATABASE_URL`, `ADMIN_LOGIN`, `ADMIN_PASSWORD`, `COOKIE_SECURE` передаются окружением. Администратор создаётся только если его логин ещё не существует; смена значения переменной не меняет пароль существующего аккаунта.

Метрики доступны только на внутреннем адресе сервера `/metrics`, не проксируются публичным Nginx. Метрики используют шаблоны маршрутов, а не идентификаторы пользователей/брони, чтобы не раскрывать данные и не создавать неограниченное количество временных рядов.
